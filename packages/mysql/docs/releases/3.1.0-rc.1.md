# @nublox/mysql 3.1.0-rc.1

`3.1.0-rc.1` is the first NuBloxSQL release candidate built from the mastered `mysqljs/mysql` lineage. It targets Node.js 22 and newer and current MySQL 8.4 and 9.x servers.

## Release-candidate scope

This RC is intended to validate the modern NuBlox connector surface before the stable `3.1.0` release. No new feature work should enter the RC line unless it fixes a release-blocking correctness, compatibility, security or packaging issue.

## Highlights

### Modern application surface

- CommonJS and native ESM entry points.
- Promise API plus `connection.promise()` and `pool.promise()` compatibility.
- TypeScript declarations.
- AbortSignal-aware Promise text queries.
- async iterable / stream consumption.
- `withTransaction()` orchestration with bounded retry support.
- pool health, saturation and diagnostics-channel observability.

### Modern MySQL authentication

- `caching_sha2_password` fast authentication.
- TLS full authentication.
- RSA non-TLS full authentication with public-key pinning/retrieval policy.
- `sha256_password` and pluggable authentication handling.
- live validation against MySQL 8.4 and 9.x.

### Prepared statements and binary protocol

- native prepare/execute/reset/close lifecycle.
- callback and Promise `execute()`.
- bounded prepared-statement LRU cache with stats and diagnostics.
- named placeholders.
- explicit typed numeric, decimal, text, binary, temporal, JSON, BIT and YEAR parameters.
- binary result decoding across numeric, temporal, string/binary, JSON, enum/set, geometry and NULL families.
- safe one-shot reprepare for stale server statement handles.

### Performance and transport

- zlib and zstd transport compression with negotiated fallback policy.
- compressed packet framing, sequence validation and bounded decompression.
- O(1)-amortized parser pending-buffer dequeue and single-buffer completion fast path.
- geometric PacketWriter growth.
- single-packet header-headroom reuse, eliminating the common final payload-sized framing allocation/copy.
- native stream backpressure.
- deterministic pool warmup and optional continuous minimum-idle maintenance with bounded retry/backoff.
- reproducible parser, PacketWriter, pool, streaming, prepared, bulk and compression benchmark harnesses.
- long-duration parser/PacketWriter memory-soak profiling.

## Command concurrency policy

Classic-protocol commands remain serialized per MySQL connection. NuBloxSQL accepts queued application operations, but only one command sequence is active on the wire at a time and packet numbering resets at each command boundary. Independent parallel work should use separate pool connections.

See `docs/architecture/query-pipelining.md` for the protocol rationale and future-safe concurrency options.

## Compatibility validation

The RC CI matrix validates:

- Node.js 22, 24 and 26;
- MySQL 8.4 and 9.x live authentication and compatibility;
- zlib and zstd transport;
- pool warmup and minimum-idle maintenance;
- stream backpressure;
- mysql2 query, pool, prepared, named-placeholder and lifecycle compatibility targets;
- typed prepared parameters and binary result decoding;
- ESM/CommonJS entry points;
- package publish surface through `npm pack --dry-run`.

## RC acceptance policy

Before promotion to stable `3.1.0`:

1. the complete CI matrix must remain green;
2. release-package verification must pass from a clean checkout;
3. any RC defect affecting data correctness, authentication, protocol framing, prepared statements, pool lifecycle or package loading is release-blocking;
4. benchmark changes must be investigated when they indicate a structural allocation or throughput regression, but noisy hosted-runner timing alone is not a release blocker;
5. stable promotion should not introduce new feature scope.

## Deliberately deferred beyond 3.1.0

The following roadmap items are not RC blockers and remain later milestones:

- enterprise hard allocation limits and composed operation deadlines;
- circuit-breaker / adaptive pool admission hooks;
- short-lived credential providers and stronger TLS profile policy;
- OpenTelemetry/query-attribute integration;
- CDC/binlog support, server-side prepared cursors, topology discovery and read/write routing.
