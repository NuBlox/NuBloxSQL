# NuBloxSQL 1.1.0

## Release objective

NuBloxSQL 1.1.0 is the first npm release of the consolidated single-entry `nubloxsql` platform package.

It preserves the stable native MySQL and PostgreSQL foundations established by the historical v1 baseline while making one install and one public API the canonical developer experience.

## Public package

```text
nubloxsql@1.1.0
```

The package contains the shared client/runtime surface and the supported native dialect implementations. Dialect runtimes are implementation modules, not independent npm package boundaries.

## Included platform capabilities

- `createClient()` portable database client;
- tagged SQL and identifier/parameter handling;
- native MySQL and PostgreSQL access through the same installation;
- SQLite runtime development surface;
- SQL Server runtime and public-client integration currently present in the consolidated tree;
- transactions, prepared statements, streaming, metadata/introspection, type codecs, operation controls and observability exposed through the platform contract where supported;
- capability and descriptor discovery;
- zero third-party declared npm dependencies.

## Compatibility

- Node.js 22 or newer remains the package engine floor.
- SQL Core contract family remains `1.0`.
- Vendor-specific behaviour remains first class rather than being hidden behind false portability.
- The historical `v1.0.0` tag remains unchanged as evidence of the earlier multi-package release baseline; it is not rewritten to represent the later consolidated package architecture.

## Distribution

- `package.json` is versioned `1.1.0`, public and release-gated.
- `prepublishOnly` runs the complete release gate.
- CI verifies Node.js 22/24/26, the proprietary boundary, the single-package architecture and the packed npm payload.
- `.github/workflows/publish-nubloxsql.yml` provides OIDC trusted publishing for subsequent tagged releases after the package has been bootstrapped in npm.
- The first npm publication must be performed by an authenticated maintainer because npm requires a package to exist before a trusted-publisher relationship can be configured.

## Release tag

The intended tag is:

```text
v1.1.0
```

The tag must point to the exact green commit on `main` containing version `1.1.0`.
