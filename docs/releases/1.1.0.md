# NuBloxSQL 1.1.0

NuBloxSQL 1.1.0 is the consolidated single-entry `nubloxsql` release line.

## Package contract

- one public npm package: `nubloxsql`;
- Node.js 22 or newer;
- proprietary licence;
- zero declared third-party npm dependencies;
- one public API routing to native dialect runtimes.

## Qualified Tier-1 dialects

- PostgreSQL 15–18;
- MySQL 8.4 and 9.7;
- SQLite through the supported Node.js 22/24/26 `node:sqlite` runtimes.

SQLite qualification includes runtime/lifecycle, storage and WAL policy, maintenance, feature fidelity, diagnostics, changesets, resource governance, deterministic errors, production performance, memory behaviour, WAL/rollback contention and corrupt-input hardening.

SQL Server remains available as the supported Tier-2 native TDS runtime and has dedicated protocol, type, streaming and live qualification coverage.

## Platform surface

The release includes unified clients, tagged SQL, typed binds, prepared execution, transactions, streaming, metadata/introspection, operation controls, observability, portable errors, capability discovery and the Tier-1 SQL capability model. Vendor-specific runtime APIs remain available where a portable abstraction would lose important semantics.

The capability model now also exposes a versioned executable SQL capability ontology through `capabilityOntology` / `capabilityModel.ontology`. It projects the existing exhaustive Tier-1 inventory into stable atomic definitions and separates engine support, conditional availability, lifecycle maturity and NuBlox parser/AST/validator/renderer/rewrite implementation coverage. Legacy capability paths and compatibility APIs remain supported.

Metadata snapshots additionally provide a versioned portable metadata v1 projection alongside the native-rich metadata surface. The projection normalizes common schema concepts without discarding native evidence and is included in the public TypeScript contract.

Tier-1 clients additionally provide `client.diagnose(statement, options)`, a versioned shared query-diagnostics contract for PostgreSQL, MySQL and SQLite. The portable report normalizes only defensible common plan metrics and retains the complete native engine report. PostgreSQL/MySQL execution analysis is available with `analyze: true`; SQLite remains plan-only through this portable entry point. SQL Server returns an explicit unsupported result until a qualified native plan implementation is added.

## User documentation

The released [user-guide suite](../guides/README.md) provides task-oriented guidance for installation, connection/pool configuration, SQL binding, prepared statements, transactions, streaming and operation control, metadata, errors/retries, observability and type codecs, dialect-specific behaviour, capability/portability analysis, TypeScript and production troubleshooting.

The released [cookbook](../cookbook/README.md) adds worked application recipes for portable CRUD, joins/CTEs/reporting, transaction/retry workflows, large-result streaming, schema tooling, query diagnostics, PostgreSQL/MySQL/SQLite/SQL Server services, bulk data movement, operational telemetry and migration analysis.

## Release qualification

The repository release gate validates source architecture, proprietary boundaries, the public package manifest, packed-package contents, clean JavaScript and TypeScript consumer installation, Tier-1 evidence, the required user-guide set and the required cookbook set. The capability ontology implementation, qualification test and declaration surface are included in the machine-enforced Tier-1 evidence register.

```bash
npm run verify
npm run test:sqlite-production
npm run release:check
```

The exact machine-readable release contracts are `public-api-v1.json` and `tier1-stable-evidence.json` in this directory.
