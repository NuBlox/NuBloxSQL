## WP10 first actionable correctness gap

For P007, the current bounded length reader is also used for acknowledgement counters. The two contexts have different requirements: buffer sizes must remain bounded and exactly representable as numbers, whereas the server's affected-row and insert-ID fields can carry unsigned 64-bit numeric values. An acknowledged write may have already committed when the parser rejects its valid large identifier. A fix must preserve successful acknowledgements, avoid silent rounding, and explicitly preserve or version public API semantics.

Acceptance: exact values for 0, 250, 251, 65535, 65536, 16777215, 16777216, 2^53-1, 2^53, and 2^64-1 in either count; truncated and invalid markers rejected; unchanged allocation guards and small-value results; real MySQL BIGINT UNSIGNED AUTO_INCREMENT insert above 2^53 followed by exact query and same-session reuse; audit affectedRows/insertId consumers, public contract lock and serialisation. WP10 candidate chooses number for safe values and bigint otherwise; this widens the preview TypeScript contract and requires documented compatibility review before merge. Allocation lengths still reject values beyond the safe range.
